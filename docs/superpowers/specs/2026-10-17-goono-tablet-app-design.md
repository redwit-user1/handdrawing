# 구노 연구노트 태블릿 앱 — 설계 (2026-10-17)

> 이 문서는 `app/`에 이미 있는 태블릿 앱(2026-09-29~30 작업, `app/README.md`, `app/docs/SYNC-API.md`)을
> **이어서 완성**하기 위한 설계다. 기존 문서와 다른 부분은 이 문서가 우선한다.
> 표기: **[사용자 결정]** 은 대화에서 사용자가 정한 것, **[Claude 판단]** 은 작성자가 정한 것(뒤집어도 됨),
> **[기존]** 은 기존 앱·문서에 이미 있는 것.

## 1. 목적과 이유

온프레미스 구노(Goono-ELN)를 쓰는 기관의 연구원이 **웻랩처럼 인터넷이 안 되는 곳에서도 태블릿으로 손글씨
중심의 연구노트를 쓰고**, 연결되면 자기 구노 계정으로 올린다. 노트 내용은 태블릿 → 구노 **단방향**이다.
[사용자 결정]

궁극적인 목표는 **연구원이 짧은 주기로 제3자 점검을 받아 시점인증이 계속 쌓이게 하는 것**이다. 구노에서
시점인증은 제3자의 점검·승인이 끝난 노트에만 붙으므로(자동 시점인증은 하지 않는다), 시스템이 할 일은
"점검을 자주, 쉽게 받게 만들고, 점검자도 빨리 승인하게 만드는 것"이다. [사용자 결정]

## 2. 사용 장면

| # | 장면 | 누가 |
|---|---|---|
| A | 웻랩(오프라인)에서 패드로 바로 쓴다. 쓰는 동안 버전이 기기에 쌓이고, 연결되면 구노 노트 하나에 버전으로 올라간다 | 연구원 |
| B | 굿노트·에버노트에서 쓴 필기를 "공유 → 구노 노트"로 보내 새 노트로 만들고, 그 위에 덧쓴 뒤 올린다 | 연구원 |
| C | 점검 주기가 되면 패드가 알린다 → 한 번에 "작성 완료 + 점검 요청(점검자 선택)" → 같은 프로젝트로 **이어 쓰기** 새 노트가 열린다 | 연구원 |
| D | 점검자가 웹에서 승인 → 기존 스케줄러가 시점인증. 점검 대기가 쌓이거나 오래되면 점검자에게 알림 | 점검자 |
| E | 연구책임자·관리자가 "점검을 N일 넘게 안 받은 노트", "N일 넘게 승인 대기 중인 요청" 현황을 본다 | 책임자·관리자 |
| F | 기기를 잃어버리면 웹에서 기기 사용 중지 / 편집권 회수 | 연구원·관리자 |

## 3. 목표 · 비목표 · 반목표

### 목표
- **G1 오프라인 작성** — 인터넷 없이 쓰고 기기에 안전하게 보관. [기존]
- **G2 버전 누적** — 패드 노트 하나 = 구노 노트 하나, 버전은 덮어쓰지 않고 쌓인다. [사용자 결정 / 기존]
- **G3 신규 생성** — 언제든 새 노트를 만들 수 있다. 여기에 더해 (a) 점검 요청 직후 **이어 쓰기** 새 노트,
  (b) 지금 노트의 페이지를 복사해 **새 노트로 시작**. [사용자 결정: 버전 + 신규 둘 다 / (a)(b)는 Claude 판단, 사용자 "얼추 맞다"]
- **G4 굿노트·에버노트 필기 가져오기** — 공유 시트(iOS) / 공유 인텐트(Android)로 PDF·이미지를 받아 노트 페이지로. [사용자 결정]
- **G5 연구원 점검 유도** — 노트별 점검 기한 표시, 기한 알림, 패드에서 바로 점검 요청, 요청 후 이어 쓰기. [사용자 "얼추 맞다"]
- **G6 점검자·관리자 유도** — 점검 대기 알림·재알림, 지연 현황. [사용자 "얼추 맞다"]
- **G7 시점인증 누락 방지** — 점검 완료 후 하루 안에 처리 못 하면 영영 빠지는 스케줄러 문제 수정. [사용자 "얼추 맞다"]
- **G8 구노 서버 API 구현** — `SYNC-API.md` v1 + 이 문서의 추가분. 웹 세션과 분리된 기기 토큰 인증.
- **G9 기관별 빌드 없음** — 앱 하나를 배포하고 서버 주소는 연결용 QR에서 받는다. [기존 + 변경]
- **G10 SSO 기관에서도 연결** — 대부분의 고객 기관이 SSO로 로그인하므로, 패드는 비밀번호를 받지 않고
  **로그인된 구노 웹에서 띄운 QR(일회용 연결 코드)로 연결**한다. [사용자 결정: 대부분 SSO 사용]

### 비목표 (이번 범위 밖)
- 구노 → 패드 **내용** 내려받기(웹에서 만든 노트를 패드에서 이어 쓰기). 내려오는 것은 기준 정보뿐이다. [사용자 결정: 단방향]
- 점검 없이 붙는 **자동 시점인증**. [사용자 결정: 제3자 점검·승인이 필요해서 거부]
- 패드에서의 **자가 점검** 요청, 패드에서의 점검 **승인**(점검자 역할). 점검 승인은 웹에서만. [Claude 판단]
- 반려(REJECT)된 노트를 패드에서 다시 고치기 — 반려된 노트는 웹에서 고친다(편집권이 이미 웹에 있음). [Claude 판단]
- 클라우드 구노, 여러 사람이 한 대를 같이 쓰는 공용 태블릿, 실시간 공동 편집. [Claude 판단: 1인 1대]
- 구노 기존 웹 API의 인증 구멍 수정(§9.4) — 이번 작업에서 새로 만드는 API만 안전하게 만들고, 기존 구멍은 별도 과제로 보고한다.

### 반목표 (기술적으로 돌아가도 이러면 실패)
- 올리기 전에 기기의 기록이 사라진다.
- 구노에 올라간 내용이 기기에서 쓴 것과 다른데 아무도 모른다(해시 검증 누락).
- 기기 토큰으로 노트 **내용**을 읽을 수 있다(기기 분실 시 피해 범위가 넓어짐).
- 태블릿 때문에 같은 사람의 PC 브라우저 세션이 끊긴다(구노 웹은 계정당 동시 세션 1개).
- **패드 경로가 기관의 자기 점검 규칙을 우회**한다. `main`의 구노는 점검자가 요청자 본인이면 그 점검을 즉시 승인
  처리하고(`ElnNoteInspctnService.createInspctnReqst`의 `isSelf` 분기), 본인 제외 여부는 기관 설정
  `note.inspection.exclude-self.enabled`(기본 false)로 정한다. KBSI 계열은 노트별 `selfInspctnAllowYn`을 쓴다.
  패드는 **그 서버 라인의 기존 규칙을 그대로 따른다** — 설정이 본인을 막으면 패드도 막고, 웹 점검 코드는 바꾸지 않는다.
  [Claude 판단]
- 가져온(굿노트 등) 내용이 패드에서 그 시각에 직접 쓴 것처럼 보인다(출처 구분 없음).
- 알림이 너무 잦아 다들 끄고 무시한다.
- 고객 기관마다 앱을 따로 빌드해야 한다.
- SSO를 쓰는 기관에서 패드를 연결할 수 없다.

## 4. 이미 있는 것 (그대로 쓴다)

`app/README.md`의 "동작 방식" 표와 `app/docs/SYNC-API.md` 전체가 기준이다. 요약:

- Capacitor 8 + React 19 + TypeScript, iPad·갤럭시 탭. 필기 엔진은 웹 손글씨 편집기와 같은 `js/engine.js`.
- A4 본문 비율 페이지 노트, 펜·형광펜·지우개·올가미·글상자·도형, 사진·표·수식·화학식·구조식·날짜 도장.
- 작업본은 기기에 AES-GCM 256 암호화(키: iOS 키체인 / Android 키스토어). 버전은 전체 스냅숏,
  노트를 떠날 때·백그라운드 진입·5분마다·수동으로 만든다. 온라인이면 1분마다 동기화.
- 버전 형식: 페이지마다 PNG(1440×2136) + editor-ai 손글씨 블록 HTML
  (`figure.rw-drawing[data-strokes][data-drawing-sha256]`), `contentHash`로 손상 검출, `clientVersionId`로 재전송 안전.
- 편집 위치(노트마다 기기 또는 웹 하나), 작성 완료 = 편집권 반납, 편집권 회수, 미반영 기록 보관·새 노트로 복원.
- 오프라인 작성 기한 = 기기 토큰 만료(기본 14일), 시계 되돌리기 감지, 기기 폐기 시 잠금.
- 모의 서버(`app/mock-server/server.mjs`), 단위 테스트, 15단계 E2E.
- 웹 쪽: Goono-ELN·redwit-editor의 `claude/handwriting-editor-integration-check-ktdg1j` 브랜치에
  앱이 올린 페이지 노트를 웹 에디터에서 여는 작업이 있다.

**프로젝트 선택**은 기존대로 패드에서 한다(구노에서 프로젝트 목록만 받아 옴). [Claude 판단 — 대화에서 추천했고
사용자가 반대하지 않음]

**바뀌는 것 — 계정 연결**: 기존 앱은 패드에서 구노 아이디·비밀번호로 로그인한다. 대부분의 고객 기관이 SSO를 쓰므로
이 방식은 기본 경로에서 빼고 **QR 연결**(§6.0)로 바꾼다. 비밀번호 로그인은 서버 설정으로 켤 수 있는 보조 경로로만
남긴다(기본 꺼짐, 개발·모의 서버용). [사용자 결정: 대부분 SSO / 방식은 Claude 판단]

## 5. 전체 구조

```
[태블릿 앱]  ── 기기 토큰(Bearer) ──▶  /api/app/v1/*  ──▶  [Goono-ELN]
   │  올라감: 노트 생성, 버전, 작성 완료+점검 요청                      │
   │  내려옴: 사용자, 프로젝트, 점검자 후보, 정책, 노트 상태             ├─ 웹: 노트 보기(손글씨 블록), 점검 승인
   │         (내용은 내려오지 않음)                                   ├─ 스케줄러: 점검 완료 → PDF → 시점인증
   └─ 로컬 알림(점검 기한) — 오프라인에서도 동작                        └─ 스케줄러(신규): 점검 지연 재알림
```

## 6. 태블릿 앱 변경

### 6.0 기기 연결 — QR (G10)
- 연구원이 PC나 패드 브라우저로 구노 웹에 평소처럼(SSO 포함) 로그인 → "태블릿 연결" → 화면에 QR과 8자리 연결 코드.
- 패드 앱의 첫 화면은 "QR로 연결". 카메라로 QR을 읽으면 **서버 주소와 연결 코드를 함께** 받으므로 주소를 입력할 필요가
  없다. 카메라를 쓸 수 없으면 서버 주소 + 연결 코드를 직접 입력한다.
- QR 내용 예: `goono-note://pair?server=https://eln.example.ac.kr&code=K7Q2-M9XD`. 연결 코드는 **일회용, 5분 유효**.
- 토큰 기한(오프라인 작성 기한, 기본 14일)이 지났거나 기기가 사용 중지된 뒤 다시 쓰려면 같은 QR 연결을 다시 한다.
  같은 계정으로 다시 연결하면 기기 데이터를 이어 쓰고 대기 기록을 올린다(기존 "재로그인" 규칙과 같음).
  다른 계정이면 기존 규칙대로 올리지 않은 기록이 있는 한 거부한다.
- 앱 안의 "서버 없이 체험하기"(데모)는 유지한다.

### 6.1 굿노트·에버노트 가져오기 (G4)
- **받는 길 3개**: iOS 공유 시트(Share Extension 타깃 추가, App Group 공유 컨테이너에 파일을 두고 본 앱이 열릴 때
  가져온다), Android 공유 인텐트(`ACTION_SEND`/`ACTION_SEND_MULTIPLE`, `application/pdf`, `image/*`),
  앱 안의 "파일에서 가져오기"(문서 선택기 — 공유가 안 되는 앱 대비).
- 굿노트·에버노트는 필기를 획 데이터로 내보내지 않는다. PDF나 이미지로만 받는다.
- **PDF는 페이지마다 이미지로 렌더링**해서 새 노트의 각 페이지 **배경**으로 깐다. 배경은 지우개·올가미로
  지워지거나 움직이지 않고, 그 위에 덧쓴다. PDF 렌더러는 앱에 번들(외부망 없이 동작)한다.
  A4 비율이 아닌 페이지는 비율을 유지해 맞춘다.
- **배경은 사진과 같은 방식으로 저장한다**: 획 데이터 안의 `tool: 'image'` 객체 + 잠금 표시(예: `locked: true`,
  `kind: 'imported-page'`). 그래야 반려 후 웹에서 노트를 고칠 때(웹 에디터는 `data-strokes`로 다시 그린다)
  가져온 페이지가 사라지지 않는다. 잠금 표시는 공용 엔진 `js/engine.js`에서 처리하므로 웹·앱 모두에 적용된다.
  손글씨 블록 크기가 커지므로 쪽수 상한을 둔다. [Claude 판단 — 리뷰 지적 반영]
- **출처 표시**: 가져온 페이지에는 "가져옴 · 파일명 · 가져온 시각"을 페이지 머리글과 손글씨 블록 데이터
  (`layout`의 페이지 메타)에 남긴다. 구노 웹에서도 보여야 한다(반목표: 출처 구분 없음).
- 원본 PDF 파일 자체는 서버에 올리지 않는다. 올라가는 것은 기존 버전 형식(페이지 PNG + 손글씨 블록)이다. [Claude 판단]
- 가져오기는 오프라인에서도 된다. 쪽수·파일 크기 상한과 경고는 빌더가 정한다.

### 6.2 점검 유도 (G5)
- **노트별 점검 기한**: 구노에서 노트는 한 번 점검 요청하면 잠기므로, 기준 시각은 **노트 생성 시각**이다.
  기한 = 생성 + `inspectionCycleDays`(기관 정책, §7.4). 이어 쓰기 노트는 새 기한으로 시작한다. 노트 선반 카드와
  노트 상단 상태 알약에 "점검 기한 D-2", "점검 기한 3일 지남"처럼 보인다. [Claude 판단 — 리뷰 지적 반영]
- **알림**: OS 로컬 알림(오프라인에서도 동작)을 **하루에 한 번, 기한이 다가오거나 지난 노트를 모아서** 보낸다
  (노트마다 따로 보내지 않는다 — 반목표: 알림 피로). 앱을 열면 기한이 지난 노트를 배너로 보여 준다. 사용자가 노트
  단위로 "이번 주기 알림 끄기"를 할 수 있다. [Claude 판단]
- **점검 받기(한 번에)**: 노트 상단 또는 알림에서 "점검 받기" →
  1. 점검자 선택: (a) 프로젝트 정책이 지정한 점검자(웹의 자동 선택과 같은 규칙), (b) 이 기기에서 최근에 고른 점검자,
     (c) 온라인이면 웹과 같은 이름 검색. 기관 사용자 전체 목록은 기기에 두지 않는다(분실 시 노출 최소화).
     오프라인인데 고를 사람이 없으면 요청을 저장해 두고 연결되면 점검자를 고르게 한다. 본인 허용 여부는 서버 라인의
     기존 규칙을 따른다(§3 반목표). [Claude 판단 — 리뷰 지적 반영]
  2. 요청 코멘트: 필수, 200자 이하(구노 웹과 같은 규칙). 기본 문구를 채워 둔다.
  3. 확인 → 마지막 버전을 만들고, 노트는 읽기 전용이 되고, **이어 쓰기 노트가 바로 열린다**.
  4. 오프라인이면 요청을 기기에 대기시키고 다음 동기화 때 "남은 버전 모두 올리기 → 점검 요청" 순서로 보낸다.
     대기 중임을 노트에 표시한다.
- **이어 쓰기 노트**: 같은 프로젝트, 제목은 "원래 제목 (이어서)" 기본값, 이전 노트와 연결(`continuesNoteId` /
  서버 `continuesNoteMno`). 첫 페이지 머리글에 "이전 노트: 제목·날짜"를 표시한다.
- 점검 요청 후 그 노트의 상태(점검 중 / 완료 / 반려, 시점인증 여부)는 노트 상태 API로 내려받아 선반에 보여 준다.
  반려되면 알림을 띄우고 "웹에서 수정하세요"라고 안내한다(비목표: 패드에서 반려 노트 수정).
- 기존 "작성 완료(편집권 반납만)"는 남겨 둔다. 점검 요청 없이 웹에서 마무리하고 싶은 경우를 위해서다.

### 7.1 기기 API — `SYNC-API.md` v1 구현
- **별도 Spring Security 필터 체인**을 `/api/app/v1/**`에 더 높은 순서로 둔다: 세션 없음(stateless),
  `Authorization: Bearer` 토큰 필터, `/devices/pair`(와 켜져 있을 때의 `/devices/register`)만 익명 허용, 나머지는 **인증 필수**.
  토큰이 맞으면 기존 서비스가 그대로 동작하도록 `UserDetailsVO`를 `Authentication.details`에 넣는다
  (`SessionHelper.getUserMno()`가 이 값을 읽는다). 기존 체인의 `maximumSessions(1)`에 걸리지 않아야 한다.
- 기존 `AuthorizationChecker`는 `/api/`로 시작하면 무조건 통과시키므로(§9.4), 새 체인이 이 경로를 먼저
  가로채 인증을 강제해야 한다.
- 토큰: 256비트 난수, DB에는 SHA-256 해시만 저장. 테이블은 아무 데서도 안 쓰는 기존 `PL_AUTH_TOKENS`
  (TOKEN, DEVICE_ID 유니크, USER_ID, EXPIRED_DT, USER_AGENT, HASH)를 재사용하거나 `SYNC-API.md`의
  `PL_APP_DEVICE`를 새로 만든다 — 빌더 판단.
- `/devices/pair`·`/devices/register`에 시도 제한: 같은 IP에서 10분 안에 5번 실패하면 429(`Retry-After`). 틀린 코드는 어느 코드에 대한 시도인지 알 수 없으므로 코드 단위가 아니라 IP 단위로 막는다. 구노 웹 로그인에는 잠금이 없다. [2단계 계획에서 구체화]
- `/devices/register`(아이디·비밀번호)는 `app.device.password-login.enabled`(기본 false)일 때만 연다.
- CORS는 앱 웹뷰 오리진(`capacitor://localhost`, `https://localhost`)을 명시한다.
- 업로드 크기: nginx `client_max_body_size 60M`(`deploy/etc/nginx/conf.d/goono.conf`)보다 버전 하나가 커지지
  않게 정책 `maxImageBytes`와 맞춘다. 넘으면 413 `TOO_LARGE`.
- DB 변경은 `deploy/src/ddl/mariadb/`에 새 SQL 파일로 추가한다(마이그레이션 도구 없음, 키는 `FN_SEQ`).
- 버전 저장은 `SYNC-API.md`대로 `ElnNoteEditorService.createNoteEditorDtl`을 재사용한다.
  **점검 요청 전 웹은 `checkExistFileId`로 노트 파일(FILE_ID)이 있는지 확인한다** — 패드에서 올린 버전도
  FILE_ID가 생기는지 확인하고, 안 생기면 웹과 같은 방법으로 만들어야 점검·시점인증 PDF 변환이 된다.

### 7.4 점검 유도 (G5·G6)
- 정책은 기존 방식대로 `config/eln.properties`에 둔다 [Claude 판단]:
  `note.inspection.cycle.days`(기본 7), `note.inspection.remind.after.days`(점검자 재알림 기준, 기본 3),
  `note.inspection.nudge.since`, `note.timestamp.since`, `app.device.enabled`, `app.device.offline-grace-days`(기본 14),
  `app.device.password-login.enabled`(기본 false).
- **점검자 알림**: 점검 요청이 오면 기존 사용자 알림(`PL_USER_NOTI`) + 웹 푸시(`system/serviceworker`)로 알린다
  (기존 요청 알림이 이미 있으면 그대로). 승인 대기 `remind.after.days`를 넘으면 하루 한 번 재알림 — 신규 스케줄러.
- **연구원 웹 대시보드**: "점검 기한이 지난 내 노트" 목록.
- **연구책임자·관리자**: 프로젝트별 "점검 기한 지난 노트 수", "승인 대기가 오래된 요청" 현황 목록.
- **유도 기능은 노트 출처(웹/앱)와 상관없이 구노 전체 노트에 적용한다.** [사용자 결정] 점검 기한 계산은 앱과 같은
  규칙(노트 생성 시각 + 주기, §6.2)을 쓴다. 기존에 작성 중이던 노트가 첫날 한꺼번에 "기한 지남"이 되지 않도록
  `note.inspection.nudge.since`(기본값은 배포일) 이후 생성된 노트만 센다. [Claude 판단]
- 웹에서 쓴 노트의 연구원 알림은 웹 사용자 알림·웹 푸시로 하루 한 번 묶어서 보낸다(패드와 같은 규칙).

### 7.5 시점인증 누락 수정 (G7)
- `elnNote-mapper.xml`의 `selectListConfirmOKConvertPDF`가 `INSPCTN_COMPLETE_DT >= NOW() - 1일` 조건 때문에
  하루 안에 처리 못 한 노트를 영영 놓친다. 이 조건을 "시점인증 기록이 없는 COMPLETE 노트 전부"로 바꾸고,
  오래된 것부터 한 번에 정해진 수만 처리한다(배포 직후 과거 노트가 한꺼번에 몰리지 않게).
- TSA 실패가 반복되는 노트가 매분 계속 재시도되지 않게 실패 횟수·다음 시도 시각을 남긴다. 일정 횟수 이상 실패하면
  관리자 현황에 보인다.
- **소급하지 않는다**: 운영 TSA(아마노 / e-note)는 노트마다 호출하는 외부 서비스라, 기준일 없이 조건을 없애면
  첫 실행에 과거의 미인증 완료 노트가 전부 오늘 날짜로 시점인증된다. 기준일 설정(`note.timestamp.since`, 기본값은
  배포일) 이후 점검 완료분만 자동 처리하고, 그 이전 누락분은 관리자 현황에 목록으로만 보여 준다. [Claude 판단 — 리뷰 지적 반영]

## 9. 보안
1. 기기 토큰은 웹 세션과 분리, 해시 저장, 사용 중지 가능. [기존 설계]
2. 기기 토큰으로 내려받을 수 있는 것은 기준 정보와 노트 상태뿐, 노트 내용은 없음.
3. 패드 경로의 본인 점검자 규칙(§7.2). 연결 코드는 일회용·5분·해시 저장·시도 제한, 비밀번호는 기본 경로에서 받지 않음(§6.0, §7.1).
4. **기존 구노 웹 API의 인증 구멍(범위 밖, 보고만)**: `framework/security/service/AuthorizationChecker.java:35-37`이
   `/api/`로 시작하는 요청을 로그인 여부와 무관하게 통과시킨다. 각 서비스가 세션 사용자를 확인하는 데 기대고 있어,
   예를 들어 프로젝트 없는 노트 생성은 DB NOT NULL 제약 외에는 막는 장치가 없다. 새 `/api/app/v1`은 §7.1의
   별도 체인으로 이 경로와 분리한다.

- **계약 테스트**: 기존 E2E 시나리오를 모의 서버 대신 실제 Goono-ELN 개발 서버에 돌려 통과해야 출시할 수 있다.
  개발 서버는 있으나 지금은 접속 정보가 없다 [사용자 답변]. 그래서 개발은 로컬에서 서버를 빌드·실행(MariaDB 컨테이너 등)해
  통합 테스트까지 하고, 개발 서버 계약 테스트는 접속 정보를 받는 대로 출시 전 관문으로 돌린다. 로컬 빌드가 막히면
  (이전 세션: Maven Central 429, 사설 패키지 저장소 인증) 그 사실과 실행하지 못한 검증 목록을 남긴다.
- 스케줄러: 하루 넘게 처리 못 한 COMPLETE 노트가 시점인증되는지, TSA 실패 재시도 간격.
- 실기기: iPad + Apple Pencil, 갤럭시 탭 + S Pen (`app/README.md` 목록).

## 11. 리뷰 후 사용자 답변 (2026-10-17)
1. 서버 코드 라인은 **`main`**. 웹 손글씨 연동을 먼저 `main`으로 이식한다(§7.0).
2. 고객 기관 **대부분이 SSO** → 패드는 QR 연결(§6.0).
3. 점검 유도는 **구노 전체 노트**에 적용(§7.4).
4. 개발 서버는 있으나 지금은 접속 정보가 없음 → 로컬 검증 후 출시 전 관문으로 계약 테스트(§10).

## 11-1. 작성자가 정한 것 (확인용)
- 프로젝트는 패드에서 고른다(§4). 1인 1대.
- QR 연결: 일회용 8자리 코드, 5분 유효, 같은 IP 10분 5회 실패 시 429. 비밀번호 로그인은 설정으로만 켜는 보조 경로(§6.0, §7.1). `app.device.enabled` 기본값은 꺼짐(기관이 켜야 사용).
- 유도 집계는 배포일 이후 생성된 노트만(§7.4).
- 자기 점검 허용 여부는 서버 라인의 기존 규칙을 따른다(§3).
- 점검 기한은 노트 생성 시각 기준, 알림은 하루 한 번 묶어서(§6.2).
- 점검자 후보: 지정 점검자 + 최근 고른 사람 + 온라인 검색, 전체 목록은 기기에 두지 않음(§6.2).
- 가져온 페이지는 잠긴 이미지 객체로 저장해 웹 편집 후에도 유지(§6.1). 원본 PDF는 올리지 않음.
- 반려된 노트는 웹에서 고친다. 점검 승인·자가 점검 요청은 패드에서 하지 않는다.
- 시점인증 누락 수정은 소급하지 않고 기준일 이후만(§7.5).
- 정책 값은 `eln.properties`에 둔다(§7.4).

## 12. 빌더에게 맡기는 것
- `PL_AUTH_TOKENS` 재사용 vs 신규 테이블, 재시도·멱등용 테이블 구조.
- PDF 렌더러 선택·해상도, Share Extension 구현 방식(Capacitor 플러그인 또는 직접 작성), 쪽수·크기 상한.
- QR 스캐너 플러그인(폐쇄망에서 동작해야 함 — 모델을 내려받는 방식은 피한다), 연결 코드 문자 구성.
- 알림·안내 문구, 화면 배치, 재시도 간격, 스케줄러 배치 크기.
- 패드 노트를 Synap 설정 기관에서 보여 주는 방법(§7.3), FILE_ID 생성 방법(§7.1).
